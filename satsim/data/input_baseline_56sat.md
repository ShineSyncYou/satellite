# 56星联调输入基线

这份基线对应 [sample_config_56sat_5ac_1gs.json](sample_config_56sat_5ac_1gs.json) 和 [walker_7x8_56_test.tle](walker_7x8_56_test.tle)，用于后端联调和功能验证。

## 1. 必需输入数据

| 参数 | 当前值 | 说明 | 设值理由 |
| :--- | :--- | :--- | :--- |
| `start_time` | `2026-04-03T00:00:00Z` | 仿真绝对起始时间 | 与测试 TLE epoch 接近，便于稳定验证 |
| `duration` | `600` | 仿真总时长，单位秒 | 10 分钟足够观察多帧接入和路由变化 |
| `time_step` | `60` | 时间步长，单位秒 | 生成 11 帧，既能看动态变化又不会太慢 |
| `tle_file` | `walker_7x8_56_test.tle` | 56 星 Walker 星座 TLE | 7 轨道面 x 8 星，规模适中 |
| `sat_mapping` | `WALKER-P-S -> sat_P_S` | 卫星固定编号映射 | 对齐 SDD 的 `sat_P_S` 规则 |
| `aircraft_traj` | `5` 架飞机、每架 `3` 个轨迹点 | 飞机轨迹插值输入 | 能覆盖不同地理位置并触发多条业务 |
| `ground_stations` | `1` 个地面站 `GS_1` | 地面固定节点 | 单目标站便于验证端到端路由 |
| `sat_antenna_angle` | `70.0` | 卫星天线半张角，单位度 | 已验证能保证 11 帧内 5 条业务全部连通 |
| `bw_gsl` | `150.0` | GSL 链路带宽，单位 Mbps | 高于单业务需求，避免过早拥塞 |
| `bw_isl` | `500.0` | ISL 链路带宽，单位 Mbps | 支撑多业务汇聚，便于观察路由而非带宽瓶颈 |
| `isl_mode` | `global-nearest` | ISL 建图模式 | 每个时间片基于卫星两两距离矩阵做全局最近邻建图 |
| `isl_max_distance_km` | `7000.0` | 单条 ISL 最大允许距离 | 过滤掉明显不合理的超远星间链路 |
| `isl_global_neighbor_count` | `4` | 每颗星保留的全局最近邻数 | 只保留满足条件的最近 4 颗卫星 |
| `isl_same_plane_neighbor_count` | `2` | 同轨保留邻居数 | 每颗星保留 2 个同轨最近邻 |
| `isl_adjacent_plane_neighbor_count` | `1` | 每侧邻轨保留邻居数 | 每颗星对前后相邻轨道面各保留 1 个最近邻 |
| `isl_require_los` | `true` | 是否要求星间视距 | 避免穿地球的非法链路 |
| `rain_fade_intensity` | `0.15` | 云雨衰落因子 | 提供轻度误码影响，但不会压垮链路 |
| `packet_size_bits` | `12000` | 单包大小，单位 bit | 约 1500 Bytes，符合常见以太网负载量级 |
| `traffic_demands` | `5` 条业务，共 `115 Mbps` | 飞机到地面站业务需求 | 总量低于汇聚瓶颈，适合功能联调 |

## 2. 节点输入明细

### 卫星

- 星座规模：56 颗
- 拓扑结构：7 个轨道面，每面 8 颗卫星
- 倾角：53 度
- 命名：TLE 名称为 `WALKER-P-S`，业务内部编号为 `sat_P_S`

### 飞机

- `AC_1`：四川向华中方向飞行
- `AC_2`：藏东向四川盆地方向飞行
- `AC_3`：华北向东北方向飞行
- `AC_4`：华南向华中方向飞行
- `AC_5`：京津冀向东北方向飞行

所有飞机高度设置在 `10.0 km` 到 `11.2 km`，符合民航巡航高度量级。

### 地面站

- `GS_1`：北京附近
- 坐标：`39.9042, 116.4074, 0.05 km`

## 3. 业务输入明细

| 源 | 宿 | 速率 Mbps |
| :--- | :--- | :--- |
| `AC_1` | `GS_1` | `25.0` |
| `AC_2` | `GS_1` | `20.0` |
| `AC_3` | `GS_1` | `30.0` |
| `AC_4` | `GS_1` | `18.0` |
| `AC_5` | `GS_1` | `22.0` |

总需求为 `115 Mbps`。在当前参数下，GSL 和 ISL 利用率都处于可观测但不过载的范围。

## 3.1 动态 ISL 规则

- 每个时间片计算一次卫星两两距离矩阵
- 仅在满足 LoS 和最大距离阈值时允许建立 ISL
- 每颗卫星从全体满足条件的卫星中保留 4 条全局最近邻边
- 然后在动态生成的 ISL 图上执行 Dijkstra

## 4. 验证结果

使用当前基线参数运行仿真后，得到如下结果：

- 共 `11` 个时间片
- 每个时间片均有 `5/5` 条业务连通
- 链路利用率范围约为 `0.0` 到 `0.7667`
- 端到端时延范围约为 `8.41 ms` 到 `87.23 ms`
- 端到端丢包率范围约为 `0.00274` 到 `0.00349`

这组参数适合做模块联调、接口验收和前端联展示例。
